# Container image analysis

This document describes some techniques and tools which can be used to study the container images generated by the NRE
build process, notably as output of CI jobs named `images*`.

## Querying image sizes without pulling

The `registry_image_sizes.py` script reports the **compressed size** of container images stored on nvcr.io by querying the
Registry V2 API. It does not pull images; it fetches the manifest and sums the config blob size and layer blob sizes.

A report from this script is printed at the end of each `images*` job.

### Usage

```bash
# Human-readable report (sizes in GiB/MiB/KiB and total)
internal/scripts/ci/image_analysis/registry_image_sizes.py --images "nvcr.io/repo1:tag1,nvcr.io/repo2:tag2,..."

# JSON output (image:tag -> size in bytes)
internal/scripts/ci/image_analysis/registry_image_sizes.py --images "nvcr.io/repo1:tag1,..." --json
```

- **`--images`** (required): comma-separated list of images in the form `nvcr.io/repository:tag`. Only nvcr.io is
  supported.
- **`--json`** (optional): print a single JSON object `{"image:tag": size_bytes, ...}` to stdout instead of a
  human-readable report.

## Studying layer contents

The `image_analysis.sh` script analyzes container images, either local or pulled from a registry, to provide insights into:

- Layer-by-layer breakdown of the image
- File (and folder) list and sizes within each layer
- Build commands that created each layer
- Registry vs. local digests and sizes for each layer
- Total image size and file count statistics

### Prerequisites

The script relies on various tools that are not installed by default on Ubuntu, notably:

- `docker`
- `dive`
- `jq`

Installation instructions are printed on screen during execution in case these dependencies are not present.

### Usage

#### Basic Usage

```bash
./image_analysis.sh <image:tag>
```

#### Examples

```bash
# Analyze the latest NRE run image from the registry
./image_analysis.sh nvcr.io/nvidian/ct-toronto-ai/nre_run:latest

# Analyze the NRE run image with the exact digest generated in job https://gitlab-master.nvidia.com/nrs/nre/-/jobs/204201020
./image_analysis.sh nvcr.io/nvidian/ct-toronto-ai/nre_run_stage@sha256:be6bc081dfa9e492256a7133c8ec4d2f8115fdd0a7e3e7ec64e78fe59577edb2
```

### Output

#### Directory Structure

The script creates an output directory with the following structure:

```text
image_analysis_results/
└── <sanitized_image_name>/
    ├── summary.txt              # Complete analysis summary
    ├── files_layer_00.txt       # Files in layer 0
    ├── files_layer_01.txt       # Files in layer 1
    ├── files_layer_02.txt       # Files in layer 2
    └── ...                      # Additional layers
```

#### Summary Report

The `summary.txt` file contains:

1. **Filesystem Layers Table**

   - Layer index
   - Registry digest and size
     - These digests are printed in CI logs and when using Docker `pull`
   - Local digest and size
     - These digests are used in Docker commands like `load` and `inspect`
   - File/folder count
   - Build command used

2. **Other Blobs**

   - Configuration blob information
   - Registry digest and size

3. **Summary Statistics**
   - Total image size
   - Total file/folder count
   - Output directory location

#### Layer Files

Each `files_layer_XX.txt` file contains:

- Header with layer metadata (digest, command, size, file/folder count)
- File/folder list in format: `filename|size|type`
- One file per line

### Example use cases

#### Understanding what contents were modified by a CI job

Jobs in NRE CI use `rules_oci` to build images and push them to a registry. Logs for the push process record information
of the form:

```bash
# This layer already exists in the registry with identical contents
existing blob: sha256:3b38896bd451905880806555489e634607eb7e9ea685655505542aab80f0d897

# No exact match was found in the registry for this layer, a new version has been pushed
pushed blob: sha256:9855025bde0545440e33351a42236d333cbbc6c3bfa0e6e6d9aad3e9f88b0772

# Name and tag of the image that was pushed, as well as its exact digest (immutable, unlike tags)
nvcr.io/nvidian/ct-toronto-ai/nre_run_stage:25.9.76-7d2147e5: digest: sha256:be6bc081dfa9e492256a7133c8ec4d2f8115fdd0a7e3e7ec64e78fe59577edb2 size: 7601
```

We can use the following commands to understand what layer saw its contents change, using the same example data as
above:

```bash
# First trigger an analysis using the image's digest:
$ ./image_analysis.sh nvcr.io/nvidian/ct-toronto-ai/nre_run_stage@sha256:be6bc081dfa9e492256a7133c8ec4d2f8115fdd0a7e3e7ec64e78fe59577edb2

# Then find the layer that was pushed using its registry digest:
$ grep "9855025" image_analysis_results/nvcr.io_nvidian_ct-toronto-ai_nre_run_stage_sha256_be6bc081dfa9e492256a7133c8ec4d2f8115fdd0a7e3e7ec64e78fe59577edb2/summary.txt
36         | 9855025bde05         | 229             | 7316c4e6c55b         | 133             | 1               | bazel build //:run_version_file_yaml_tar

# And see what files are present in this layer:
$ cat image_analysis_results/nvcr.io_nvidian_ct-toronto-ai_nre_run_stage_sha256_be6bc081dfa9e492256a7133c8ec4d2f8115fdd0a7e3e7ec64e78fe59577edb2/files_layer_36.txt
# Layer 36: sha256:7316c4e6c55b3d79e5ba9654291600a389b5b109ec98de2db0bf6877b44e6f50
# Command: bazel build //:run_version_file_yaml_tar
# Size: 133
# File count: 1
# Format: filename|size|type

version_file.yaml|133|48
```

#### Diffing images

To assess the impact of a code change, or to pinpoint unexpected variation in image contents, it can often be useful to
diff two images.

```bash
# Clean-up the results folder and process 2 images to compare:
$ rm -rf image_analysis_results
$ ./image_analysis.sh nvcr.io/nvidian/ct-toronto-ai/nre_run_stage@sha256:be6bc081dfa9e492256a7133c8ec4d2f8115fdd0a7e3e7ec64e78fe59577edb2
$ ./image_analysis.sh nvcr.io/nvidian/ct-toronto-ai/nre_run_stage@sha256:fac172b6ba377b7da522f09458e1c41e6569d66bc031fa0caf5443204b706635

# Run a diff on the results folder to see what layers and files differ between the images:
$ diff image_analysis_results/*
[...]
```

The above procedure notices files that were added/removed, or whose size changed. In the less common case where file
contents change while size remain constant, the containing layer digest will still vary and appear in the diff.

If one needs to go further with the diff analysis, tool [diffoci](https://github.com/reproducible-containers/diffoci)
can be used to not only list files whose contents have changed, but also dump them to disk for comparison.

```bash
# Diff images
$ diffoci diff --report-dir=image_analysis_results \
```
